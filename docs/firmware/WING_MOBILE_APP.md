# Мобильное приложение LiteBee и протокол Wing по Wi-Fi

Источник: два APK с официальной страницы загрузки LiteBee Wing (`LiteBee_sw.apk` 112,52 МБ, `litebee.apk` 125,38 МБ, получены 2026-11-06), разбор DEX (androguard) и ARM64-библиотек. Пометки: **ПРОЧТЕНО** (в байткоде или коде), **ВЫВОД**, **НЕИЗВЕСТНО**. Сами APK в репозиторий не кладутся.

## 1. Что внутри

* Одно приложение на несколько моделей: пакеты `c06` (Wing), `c09`, `c10` (Bot), `MR100`. Java-код обфусцирован (классы вида `a`, `b`), но ключевые классы сохранили имена.
* Нативные библиотеки (ARM64): `libflightNativeLib.so` (кадры, 23 JNI-функции), `libc09Lib.so` (C09), `libc10library.so` (только `crc16`), `libcamera.so`, `libh264lib.so`, `liblive555.so` (RTSP), `libnewMain.so` (видео MR100).
* Адреса Wi-Fi в коде (строки в `classes.dex`): `192.168.100.1` (Wing/C06), `192.168.5.1` (C10), `192.168.4.1` (C09), `192.168.99.1` (видео других моделей).

## 2. Wing (C06) в мобильном приложении (ПРОЧТЕНО)

| Что | Значение |
|---|---|
| Транспорт | **UDP**, дрон `192.168.100.1:9696`, локальный порт 12345 (`C06UdpClient`); отправка из очереди `outBytesQueues`, приём отдельным потоком |
| Строитель кадров | класс `com.makerfire.mkf.protocol.MR100.FlyContronl` (методы `takeOff`, `land`, `getModeData`, `getFlyLocation`, …) |
| Сердцебиение | `C06SendHeart`: кадр каждые 200 мс |
| Блоки Blockly | `C06FlyUtil` вызывает те же построители |
| Видео | `C06PreViewManager`, RTSP с `192.168.100.1` (порт 7070 по приложению для ПК) |

Кадр (тот же `awlink`, что в `docs/firmware/AWLINK_TABLE.md`): `0xFA, len, src, group, sub, данные[len], crc_lo, crc_hi`. `src` = 0 (`ID_SRC`). CRC-16 с начальным 0xFFFF и таблицей (`crc16([B I)I`), считается по байтам от `len` до конца данных, младший байт первым.
Совпадает с `litebee/protocol.py` (CRC-16/MCRF4XX): таблица в приложении начинается с `0, 4489, 8978, 12955`, как и в вашей проверке.

### Команды `FlyContronl` (раскладка восстановлена интерпретатором байткода, проверять на железе)

| Метод | Кадр (после `FA`) | Смысл |
|---|---|---|
| `getHeartData` | `[1, 0, 0, 3, count]` | сердцебиение, счётчик по модулю 256 (группа 0, подгруппа 3) |
| `getCorrectCommend(a,b)` | `[2, 0, 2, 2, a, b]` | калибровка (как в `live.py`) |
| `getBaseInfo` | `[2, 0, 2, 1, 0, 20]` | запрос потока базовой информации (подгруппа 1: тип 0, частота 20) |
| `getBaseSensorStatus` | `[2, 0, 2, 1, 3, 20]` | поток датчиков (тип 3) |
| `getBaseCorrectStatus` | `[2, 0, 2, 1, 4, 20]` | поток статуса калибровки (тип 4) |
| `getModeData(m)` | `[9, 0, 2, 3, m, 0,0,0, f, 0×4]` | режим `m` (взлёт = 3); `f` = 0 для режимов 3 и 12, иначе 1 (ВЫВОД по условию в коде) |
| `takeOff` | `getModeData(3)` | взлёт |
| `land`, `emergency`, `getRotate360` | существуют; кадры строятся на основе `getModeData` (ВЫВОД, тела не разбирались построчно) | посадка, аварийная остановка, оборот 360° |
| `getEngine(a,b)` | `[9, 0, 2, 3, 20, b, 0×7]` | включение/выключение моторов (команда 20) |
| `getFlyLocation(x,y,z)` | `[9, 0, 2, 3, 21, x_lo,x_hi, y_lo,y_hi, z_lo,z_hi, 0,0]` | перелёт в точку (три int16, команда 21) |
| `getDirection(a,b)` | `[9, 0, 2, 3, 22, a, b, 0×6]` | направление (команда 22) |
| `getHeadDir(a, ang16)` | `[9, 0, 2, 3, 23, a, ang_lo, ang_hi, 0×5]` | направление носа (23) |
| `buzzerControl(n)` | `[9, 0, 2, 3, 24, n, 0×7]` | зуммер |
| `getAexsSelect(n)` | `[9, 0, 2, 3, 25, …]` | выбор оси/датчика (назначение НЕИЗВЕСТНО) |
| `set_buzzer(a,b)` | `[9, 0, 2, 3, 27, 1, a, b, 0×4, 3]` | зуммер с параметрами |
| `set_ledRGB(r,g,b,t)` | `[9, 0, 2, 3, 27, 2, r, b, g, t, 0×2, 5]` | светодиод RGB (порядок цветов и последний байт ВЫВОД) |
| `getRemoteContronl(remote)` | `[8, 0, 2, 0, 8 байт стиков]` | стики (группа 2, подгруппа 0) |

Важно: **в мобильном приложении Wing перелёт, направление и поворот идут как команды подгруппы 3 (значения 20–27)**, а не как подгруппы 12/13/14 (высота, скорость, поворот), которые использует библиотека C10 и ваш `litebee/live.py`. В таблице `AWLINK_TABLE.md` (из `pilot` Wing) подгруппы 12–14 перечислены, а значения 20–27 внутри подгруппы 3 нет, так что их реализация в самом `pilot` не подтверждена (НЕИЗВЕСТНО). Значения `a`, `b` в `getDirection`, `getEngine`, `getAexsSelect` и единицы `getFlyLocation` тоже НЕИЗВЕСТНЫ.

## 3. C10 (Bot) в мобильном приложении (ПРОЧТЕНО)

* Транспорт: TCP `192.168.5.1:17788` (`C10ControlPresenter`), видео `rtsp://192.168.5.1:8554/ch0`.
* Кадры строит `libflightNativeLib.so` через `getFlightCmd(id, out, in)` и `encode`. Таблицы в `.rodata` (по номеру команды 0–10): длина данных `[2,1,8,2,5,7,3,5,9,10,20]`, группа `[2,0,2,2,2,2,2,2,2,2,2]`, подгруппа `[2,3,0,1,13,12,14,17,3,11,6]`.

| Номер | JNI | Кадр | Смысл |
|---|---|---|---|
| 0 | `calibration` | `[2,0,2,2,…]` | калибровка |
| 1 | `beatHeart` | `[1,0,0,3,count]` | сердцебиение |
| 2 | `stick` | `[8,0,2,0, 4×int16]` | стики |
| 3 | `setFlightInfo` | `[2,0,2,1,type,rate]` | запрос потока |
| 4 | `setFlightVel` | `[5,0,2,13,…5 байт]` | скорость |
| 5 | `setFlightPos` | `[7,0,2,12, байт, 3×int16]` | положение или высота |
| 6 | `setFlightYaw` | `[3,0,2,14, байт, int16]` | поворот |
| 7 | `setLinePatrol` | `[5,0,2,17, байт, int16, байт, байт]` | следование по линии |
| 8 | `setModeNoParams`, `setFlightMode`, `setFlightExt` | `[9,0,2,3, режим, …]` | режим |
| 9 | `Extent_openQRCode`, `openLinePatrol` | `[10,0,2,11, 6, режим, …]` | режим камеры (1 линия, 2 метки, 3 цвет, 4 ИИ) |
| 10 | (тест) | `[20,0,2,6, 20 байт]` | тест моторов |

Это те же кадры, что в `litebee/live.py`: `calibrate`, `takeoff`, `hold`, `land`, `velocity`, `yaw`, `height`. Значит, `live.py` повторяет раскладку C10 (и библиотеку с кадрами подгрупп 12–14), а не «команды 20–23» Wing-приложения. Библиотеку `com.makerfire.library.Control` вызывает `C10ControlPresenter` (ПРОЧТЕНО).

## 4. Поправка к `GO_APP_CAMERA_AND_UPDATE.md`

Отчёт агента по приложению для ПК утверждает, что кадры «группы 2» принадлежат только C10. Мобильное приложение показывает более сложную картину:
* Wing в мобильном приложении **тоже использует группу 2** (по UDP 9696), но в виде режимов подгруппы 3, а не подгрупп 12–14.
* Кадры подгрупп 12–14 (скорость, высота, поворот) строит библиотека C10.
* `litebee/live.py` совпадает с формой C10. Для Wing есть основание использовать форму из раздела 2 или проверить на дроне, какая принимается.

## 5. Что не выяснено

* Разбор ответов дрона (`udpRecevie`, `dataHandle`, `setBaseData`, `setFormationData`, `setExtentData` в библиотеке): раскладка телеметрии и данных камеры.
* Значения полей `a`, `b` в `getDirection`, `getEngine`, `getAexsSelect` и единицы `getFlyLocation`.
* Как соотносятся USB-пульт и UDP 9696 по порту и протоколу.
* Другие классы (C09, MR100) и видеопротокол (`libh264lib`, `liblive555`).

## 6. Инструменты

`tools/firmware/arm64_disasm.py` (дизассемблер ARM64), `apk_class_dump.py`, `apk_frame_template.py`, `apk_method_dump.py`, `apk_xref.py` (androguard). Файл DEX задаётся переменной `DEX`, список DEX в `apk_xref.py` перебирается вручную.
