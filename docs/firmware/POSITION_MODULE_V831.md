# Позиционный модуль на Allwinner V831: что внутри и какой кадр он шлёт

Источник: модуль, подключённый по USB к компьютеру (чтение через ADB; файлы скопированы, ничего не записывалось и не прошивалось), 2026-11-06. Пометки: **ПРОЧТЕНО** (в файлах или памяти работающей программы), **ВЫВОД**, **НЕИЗВЕСТНО**. Бинарники модуля в репозиторий не кладутся.

## 1. Что это за устройство (ПРОЧТЕНО)

* Плата с чипом **Allwinner V831** (маркировка на кристалле), кнопки BOOT и RST, 5V/GND, два разъёма с TX/RX, USB.
* ОС: Linux 4.9.118 (OpenWrt, ядро собрано Sipeed, хост `sipeed`), 32-бит ARM, musl, BusyBox, есть python3. Доступ по USB: ADB с правами root, плюс флеш-диск на 50 МБ (FAT16) с файлами `maix_dist.sha256sum`, `V1.0.3`, `color_config.json` (`null`).
* Программа: `/mnt/cfg/firmware/maix_dist/app_ckh831` (14 КБ) + библиотека `lib/libmaix_ckh831.so` (1,5 МБ, динамические символы **не вычищены**). Запуск: `S02app` -> `/home/firmware/keep_app.sh` (сторожевой цикл) -> `app_ckh831`.
* Обновление: если на USB-диске лежит `maix_dist/maix_dist.sha256sum`, скрипт `S02app` при старте копирует папку в `/mnt/cfg/firmware/`, удаляет её с диска и перезагружает модуль. Если программа запустилась 4 и более раз и падает, `keep_app.sh` вызывает `/home/firmware/factory.sh` (сброс). Значит, замена программы возможна без разборки, но ошибка приведёт к сбросу (ПРОЧТЕНО в скриптах).

## 2. Что делает программа (ПРОЧТЕНО по символам и дизассемблеру)

* Код `imlib` из **OpenMV** (поиск AprilTag, блобов, цвета), кроме того `lodepng`, `lvgl`, `cvflann` из OpenCV.
* В библиотеку скомпилированы таблицы семейств **tag36h11, tag36h10, tag25h9, tag25h7, tag16h5**. Программа вызывает `imlib_find_apriltags_new(0x10, ширина, высота)`: маска `0x10` в нумерации OpenMV означает только **TAG36H11** (маска в `imlib_find_apriltag_app_load`, адрес 0x3518c, `mov r0,#0x10`). ArUco в библиотеке нет.
* Датчик расстояния **VI5300** (ToF, I2C), светодиоды **WS2812** (порядок цветов GRB, как в `set_ledRGB` приложения), ШИМ, камера через V4L2, дисплей (`lvgl`).
* Открытые порты: `/dev/ttyS0`, `/dev/ttyS1`, `/dev/spidev1.0`, `/dev/i2c-2`, камера `/dev/video0` и `/dev/video1`.
* Функции протокола: `ckh831_protocol_send` (0x24144), `ckh831_protocol_recv` (0x249cc, разбор входящих `AD FA …` и `F1`), `ckh831_ctrl_loop` (0x256c8), `imlib_find_apriltag_app_loop` (0x352c0).

## 3. Кадр модуля (ПРОЧТЕНО в памяти работающей программы, 22 байта)

`ckh831_protocol_send` пишет в порт 22 байта: байт 0 = `0xCD`, байты 1–20 = данные, байт 21 = сумма байтов 1–20 по модулю 256. Буфер `global_packet_openmv` лежит по смещению `0x17e658` в `libmaix_ckh831.so`.

Кадр с меткой в поле зрения (пример: `cd 02 00 00 ff f4 00 32 01 47 02 df 01 00 00 00 00 00 39 01 00 8f`):

| Байты | Значение | Пример |
|---|---|---|
| 0 | константа `CD` | `cd` |
| 1 | тип кадра (2 = метка) | `02` |
| 2–3 | `id` метки, старший байт первым | `0000` (id 0; под камерой лежала метка 0, подтверждено владельцем) |
| 4–5 | смещение x, int16, старший первым | `fff4` (−12) |
| 6–7 | смещение y, int16 | `0032` (50) |
| 8–9 | дистанция до метки, int16 | `0147` (327) |
| 10–11 | угол поворота, int16 (менялся при вращении модуля; единицы 0,1° по сопоставлению с `pilot`, НЕ проверено) | `02df` (735) |
| 12 | флаг «метка найдена» | `01` |
| 13–14 | счётчик, u16 (в примере 0) | `0000` |
| 15–17 | нули | |
| 18–19 | расстояние ToF, uint16, **младший байт первым**, мм | `3901` (313) |
| 20 | 0 | |
| 21 | сумма | `8f` |

Проверки: сумма совпадает с формулой на большинстве кадров (часть кадров читалась в момент обновления буфера, см. раздел 6). Дистанция метки 327 близка к ToF 313 мм.
Тип кадра и расположение полей совпадают с разбором в `pilot` по пути «тип в байте 0» (`MODULE_UART_LINK.md`, раздел 5): тип 2, `id` в байтах 1–2 от начала данных, затем x, y, расстояние, курс, флаг на байте 11. Совпадение раскладки подтверждает, что это именно тот кадр.

## 4. Расхождение заголовка: объяснено (ПРОЧТЕНО в `pilot_f` дрона)

Приёмник `int_dev0` в **`pilot_f` на дроне** (март 2023, функция `0x342cc`) принимает кадр с **одним байтом заголовка**: `0xCC` (14 байт данных) или `0xCD` (20 байт данных), затем данные и контрольная сумма (сумма байтов данных по модулю 256). Данные копируются в буфер по тому же смещению, что и в более поздней версии. Кадр модуля (`CD` + 20 байт + сумма, 22 байта) совпадает с этим приёмником полностью.
В образе **Wing 1.2.8** (2025) тот же приёмник требует **два** байта заголовка (`CD CD`). Следовательно, версия программы модуля и версия `pilot` согласованы парой: модуль с одним байтом `CD` работает с `pilot` 2023 года, а для 1.2.8 нужна прошивка модуля с двумя байтами. Это важно при своей замене: формат кадра нужно подбирать под версию `pilot` на дроне (ВЫВОД по двум прочитанным приёмникам; на живом дроне приём не наблюдался, дрон отключился от ADB).

## 4a. Команды дрона к модулю (ПРОЧТЕНО в `ckh831_protocol_recv`, 0x249cc)

Кадр от дрона: `AD FA <команда> <данные…> <сумма>` (то же начало `AD FA`, что передаёт `pilot`, см. `MODULE_UART_LINK.md`, раздел 2). Длина данных определяется таблицей по номеру команды, сумма считается по данным (проверка в 0x24cd8). Данные ниже нумеруются от первого байта после команды. Разбор по дизассемблеру, на живом обмене не проверялся (ВЫВОД по коду):

| Команда | Действие |
|---|---|
| 1 | `ckh831_home_app_select(данные[0])`: выбор режима программы модуля (список режимов не разобран) |
| 2 | Выход GPIO: данные[0]: 0 -> GPIO 0xE2, 1 -> GPIO 0xE3, 0xFF -> оба; значение в данные[1] |
| 3 | Светодиоды WS2812: данные[0] номер (0, 1 или 0xFF для всех), цвет из данных[1..3], каждое значение делится на 2 |
| 4 | ШИМ каналы 1 и 2: данные[0] и данные[1] |
| 5 | Настройка цвета (6 знаковых байт, запись в JSON-конфигурацию, `color_config.json`) |
| 6 | ШИМ каналов 1 и 2 с 16-битным значением: данные[0..1], данные[2] и данные[3..4], данные[5] |
| 7, 8, 11 | не выполняют действий |
| 9 | Ответ модуля: кадр из двух байт `F9 66` (опрос присутствия или версии) |
| 10 (`0x0A`) | Снимок кадра (`ckh831_ctrl_capture`) |
| 0xF1 | данные[0] = 1 сбрасывает, 2 устанавливает флаг (адрес `+0x136` в состоянии, назначение НЕИЗВЕСТНО) |
| 0xFA | Пересылка полученных данных на второй порт (`ttyS1`) |

ШИМ и GPIO, вероятно, управляют расширениями (электромагнит и подобные, ВЫВОД по описанию набора). Какие команды дрон реально посылает при работе (за пять минут на дроне ушло 360 байт в `ttyS0`), не снято.

## 5. Следствия для ArUco и своей прошивки

* **Другое семейство AprilTag на штатном модуле.** Изменить маску с `0x10` на другую (например `0x01` для TAG16H5) можно правкой одной константы в `libmaix_ckh831.so` и заменой программы через USB-диск. Остальные 4 таблицы уже в библиотеке.
* **ArUco.** Готового кода в библиотеке нет, но модуль это полноценный Linux с библиотеками OpenCV (в манифесте есть `libopencv_*`), то есть можно написать свою программу, которая шлёт тот же кадр (раздел 3). Нужен кросс-компилятор под musl ARM (Sipeed V831 SDK).
* **Риски.** Сброс при падении (раздел 1). Перед любыми изменениями снята полная копия (`maix_dist/` и `/home/firmware`, 103 файла, около 30 МБ). Тесты без пропеллеров.

## 6. Что не выяснено

* Расхождение заголовка с `pilot` (раздел 4).
* Масштаб полей x, y, расстояния и угла в реальных единицах; кадры других типов (1, 4, 5); смысл счётчика (байты 13–14).
* Зачем модуль слушает `ttyS1` и ретранслирует байты (`ckh831_ctrl_loop`): вероятно, канал к другому расширению.
* Чтение буфера не атомарное, поэтому часть кадров попадала на границу обновления (сумма не сошлась).

## 7. Инструменты

`tools/firmware/module_dis.py` (дизассемблер ARM `.so` с символами и PLT), `tools/firmware/module_peek.py` (запускается на модуле через ADB, читает последний кадр из памяти программы). Нужен `adb` (Google platform-tools).
