# Прошивка LiteBee: что выяснено и что ещё неизвестно

Сводка на 2026-11-06 по всем источникам: образы дрона Wing, ядро C10 (`melis30_1.5.elf`), приложение LiteBee Go, два APK, позиционный модуль V831 (снят по USB/ADB). Пометки: **ПРОЧТЕНО** (видно в файлах или на живом устройстве), **ВЫВОД**, **НЕИЗВЕСТНО**. Ничего не записывалось ни в дрон, ни в модуль.

## 1. Что теперь известно (ПРОЧТЕНО)

| Вопрос | Ответ | Где |
|---|---|---|
| Кто считает положение по метке | Автопилот: `id % 12` столбец, `id / 12` строка, шаг 40 см, смещение из кадра модуля | `FIRMWARE_MARKERS.md` |

## 2. Что неизвестно, с причинами

### 2.1 Связь модуля с дроном (самое важное)
* **(Закрыто, см. ниже)** **Заголовок кадра.** Модуль шлёт один байт `CD` и тип `02`, а приёмник `int_dev0` в `pilot` по моему чтению ждёт два байта (`CD CD`). Либо я неверно прочитал автомат приёма, либо у этого дрона другой приёмник (НЕИЗВЕСТНО). Решается проверкой на дроне без пропеллеров или логическим анализатором. **Ответ:** на дроне стоит более ранний `pilot_f` (март 2023), его приёмник принимает один байт заголовка (`CC` или `CD`) и кадр модуля `CD` + 20 байт + сумма подходит полностью; в образе 1.2.8 заголовок двухбайтовый. Подробно: `firmware/POSITION_MODULE_V831.md`, раздел 4. **Живая проверка выполнена:** дрон принимает кадры модуля (`rx` растёт), буфер `pilot_f` совпадает с данными кадра (`firmware/WING_DRONE_USB.md`, раздел 5b). Не проверено: что дрон делает с флагом 1 (метка найдена) и как переводит смещения в положение.
* **Номер метки.** Во всех снятых кадрах `id` был 0, и под камерой действительно лежала метка 0 (подтвердил владелец: это файл для печати, сделанный для проверок). Это не противоречит привязке байтов 2–3 к номеру, но подтверждает её слабо: нужен кадр с ненулевой меткой.
* **Единицы.** По формуле из `pilot_f` дрона: x и y около 0,83 мм на единицу, расстояние около 1,02 мм на единицу (ToF 287 мм при расстоянии 296 совпало), угол в 0,1° (`firmware/WING_DRONE_USB.md`, 5c). Связь с калибровкой камеры модуля не выяснена, положение из памяти дрона вживую не снято.
* **Другие кадры.** Типы 1, 4, 5, 0xF9 и кадр `CE CE` в `pilot` не разобраны. Команды дрона к модулю разобраны по коду модуля (`firmware/POSITION_MODULE_V831.md`, раздел 4a); какие из них дрон шлёт на деле, не снято.
* **Выбор приёмника.** `int_dev0` или «ext device uart» определяет флаг `0x541ec`; его значение по умолчанию не прочитано.

### 2.2 Модуль V831
* Загрузчик, ядро и корневая файловая система целиком (побитовый образ не снимался, модуль отключился; есть копия файлов программы).
* Калибровка камеры и размер метки (откуда берётся масштаб 8,333 в `pilot`).
* Зачем программа слушает `ttyS1` и пересылает байты (`ckh831_ctrl_loop`).
* Формат `color_config.json` (на модуле `null`), проверка подлинности обновления (по манифесту видна только контрольная сумма, подписи не видно, не проверялось).
* Совпадает ли эта программа с той, что стоит на камере C10 (V853S).

### 2.3 Автопилот Wing
* Логика `pilot` без символов; константы регуляторов, драйверы датчиков, миссионный исполнитель известны только по названиям и по `melis` (который относится к C10).
* Закрытый алгоритм оптического потока (`flow`).
* Загрузчик и подпись образа дрона, возможность обратной прошивки.
* Какая форма команд принимается вашим Wing: подгруппа 3 (коды 20–27) или 12–14 (как у C10, в `live.py`). Проверяется на стенде.
* Связь USB-пульта и UDP 9696.

### 2.4 Протокол приложения
* Единицы полей телеметрии (напряжение, ёмкость, углы), функция `getBaseData`.
* Расхождение: «версия» в байте 57 кадра по трассировке соответствует `axisType`.
* Порядок слотов моторов в `getEngine` (мотор 1 вероятно в последнем слоте), смысл `getAexsSelect`.
* Данные камеры по Wi-Fi (группа 1, подгруппа 5): раскладка прочитана только частично.

### 2.5 Не разобрано вообще
* Прошивка пульта (`LiteBee Wing_remote_gd_v1.1.3.hex`, GD32E103).
* Linux-ядро C10 (V853S) и его камера.
* Схемы плат и разводка.
* Страницы `fast.uc.cn` (скачивались вручную, не открывались автоматически) и вики `docs.makerfire.com` (не загрузились).

## 3. Что дальше даст больше всего
0. **(Сделано 2026-11-06)** Дрон подключён по USB, ADB работает, сняты 8 разделов флеша и файлы, см. `firmware/WING_DRONE_USB.md`. Было: **Подключить по USB сам дрон (Wing).** В образе дрона запускается `adbd` (VID:PID `18D1:0002`, `etc/init.d/adbd.init`, ПРОЧТЕНО) и есть режим диска на весь флеш `/dev/mmcblk0` (`18D1:0001`, `etc/autorun.sh`). Если дрон так же отзывается, это даст: оболочку с правами root, живые журналы `pilot`, параметры (`/netPrivate/param`), побитовый образ, чтение UART `ttyS0` во время работы и проверку заголовка кадра модуля. Условия: без пропеллеров, только чтение, без записи в флеш.
1. Подключить модуль к дрону без пропеллеров и положить метку с известным номером: проверит заголовок, номер и единицы.
2. Снять побитовый образ флеша модуля (когда он снова подключён по USB): основа для своей прошивки и отката.
3. Разобрать оставшиеся функции `libmaix_ckh831.so` (калибровка, масштабы, команды `AD FA`).
