# Одиночный режим LiteBee Go: относительные команды `setDir`, `setYaw`, `setHigh`

Источник: код установленного LiteBee Go (`resources/gui/lib.min.js` и `resources/app.asar`, `main.js`). Дрон не трогали, сетевых портов не открывали. Это чтение кода, на живом дроне ничего из описанного ниже не проверено.

## Вывод одной строкой

Относительные команды (`setDir`, `setHigh`, `setYaw`, `setVZ`, `setVXYZ`, `setPosXY`) идут **только по USB-serial** (адаптер CP210x или CH340, 115200 бод), а не по Wi-Fi, которым пользуемся мы (TCP 18001). Формационный обработчик LiteBee Go (Wi-Fi) знает только `formation_*` и эти команды не принимает. Значит, программы Number tracking и `demo.py` / `Number8.py` с нашим Wi-Fi-протоколом выполнить нельзя.

## Что это за программы

| Файлы | Расширение Scratch | Как летает |
|---|---|---|
| `Number tracking- N.lbg` | `litebeeWing` | один дрон, относительные скорости на время (`setDir` + `wait`), цифра рисуется траекторией |
| `demo.py`, `Number8.py` | Python, функции `litebeeWing_*` | то же текстом |
| формации (`10-drone …`, `8-drone …`, `4-drone …`) | `litebeeWingFormation` | шаги миссии по клеткам коврика, Wi-Fi, это наш режим |

## Команды и их смысл (из GUI)

Python-функции `litebeeWing_*` принимают один список:

| Функция | Параметры | Единицы |
|---|---|---|
| `setDir([roll, X, pitch, Y])` | `roll`: 0 влево, 1 вправо; `X` скорость вбок; `pitch`: 0 вперёд, 1 назад; `Y` скорость вперёд/назад | подсказка редактора: «10 (0,1 м/с)», блок Scratch «cm/s», то есть 10 соответствует 10 см/с |
| `setYaw([dir, angle])` | `dir`: 1 по часовой, 2 против; `angle` 0–180 | градусы |
| `setHigh([z])` | высота | см |

Число 20 в Number tracking при паузе 2 с даёт путь около 40 см, то есть одну клетку коврика (вывод по сходству размеров, не проверено).

## Что уходит из GUI (сообщение `[id, ...данные]`)

Id сообщений: `set_rotate`=18, `vel_control`=27, `pos_control`=30 (таблица в `lib.min.js` и `main.js`).

| Команда | Сообщение |
|---|---|
| `setDir` | `[27, 2, 0, Y, X, 0]`; `Y` отрицательный для «назад», `X` отрицательный для «влево» |
| `setVZ` | `[27, 4, 0, 0, 0, Vz]` |
| `setVXYZ` | `[27, 6, 0, Y, X, Z]` |
| `setHigh` | `[30, 2]` + шесть байт `Int16Array([0, 0, z])`, little endian |
| `setPosXY` | `[30, 1]` + шесть байт `Int16Array([x, y, 0])` |
| `setYaw` | `[18, dir]` + байты угла (конец определения прочитан, начало нет) |

Сообщение отправляется через IPC `flight:send`. Очередь на пять сообщений: выполняется только последнее, не чаще раза в 10 мс.

## Куда оно уходит (`main.js`)

Маршрутизация зависит от текущего расширения:

| Расширение | Транспорт |
|---|---|
| `litebeeWingFormation`, `litebeeStars` | `formationDataHandle`: миссия и TCP-сервер 18001 (то, что мы реализовали) |
| `litebeeBot`, `litebeeBotML5` | TCP `192.168.5.1:17788` (другой робот) |
| `ghost2Ext` | ничего |
| остальные, в том числе `litebeeWing` | `drivers.serialSend`: байты `[253, 253, длина] + сообщение` в USB-serial; если порта нет, «Сначала подключите самолёт» |

Serial: порты с VID:PID `10C4:EA60` (CP210x) или `1A86:7523` (CH340), 115200 бод; при открытии пишется `[253, 253, 1, 233]`. Дальше USB-адаптер сам передаёт команду дрону по радио, этот отрезок в коде приложения не виден.

Формационный обработчик `handle(e)` разбирает только `formation_*`, `all_autoland`, `formation_openDemo`; ветка `user_control` пустая. Сообщений `vel_control`, `pos_control`, `set_rotate` там нет.

## Первые полёты Wing через пульт (2026-10-28), `python -m litebee wing-fly`

Дрон Wing, пульт в режиме программирования, команды из `litebee/wing.py`.

| Полёт | Что отправляли | Что вышло |
|---|---|---|
| 1 | калибровка `[10]`, взлёт `[16]`, зависание `[29,2,…]`, сдвиг `[30,4,X,Y]`, посадка `[17]` | взлёт сразу до **97 см**, высота ползла вверх до 149, на втором сдвиге крен около 45°, дрон зацепился за сетку |
| 2 | то же + команда высоты 80 см `[30,2,0,0,0,0,z,z]` | высота держалась 86–91, наклоны меньше 1°, **сдвиг `[30,4,X,Y]` дрон не выполнил** (глазами и по данным), высота росла на ~15 см на каждую такую команду |
| 3 | вместо сдвига скорость `[27,2,0,Y,X,0]` (15 см/с на 2 с), затем стоп | спокойный полёт, посадка ровная; по данным вперёд на 31 см и вправо на 33 см от точки зависания |

Выводы:
- **Команда сдвига `[30, 4, X, Y]` не работает** (оставлена в коде только для истории). Рабочий способ: скорость `[27, 2, 0, Y, X, 0]`, путь равен скорости на время; перед посадкой и после шага отправляется стоп.
- Стандартный взлёт `[16]` поднимает дрон почти на метр (90–98 см), команда высоты `[30,2,…]` опускает его до 80–86 см.
- Положение в данных пульта в этом режиме **живое**: `x` вперёд, `y` вправо (сантиметры), точность в 3-м полёте около 1–3 см относительно заданных 30 см. В покое на земле оценка может «плыть» (в записях −18/−265 дрейфовало на несколько единиц).
- **При взлёте дрон смещается**: в 3-м полёте `x` ушёл с −17 до −39 (на 22 см назад), поэтому «вперёд на 30 см» от точки зависания дал всего +7 см от точки старта на полу. Глаз видит именно смещение от старта.

Защиты полёта (в коде и тестах `tests/test_wing.py`): предварительные проверки (дрон связан, лежит ровно, батарея не ниже 7,4 В, нет файла `LAND_NOW`), посадка при наклоне больше 30°, высоте больше 130 см, потере данных на 1 секунду, батарее ниже 6,6 В, Ctrl+C и любой ошибке.

## Живые команды: кадры группы 2 (новый класс расширений Wing)

В `lib.min.js` есть второй, более новый класс расширений Wing (режимы «метки», «линия», «цвет», «ИИ»). Он собирает не сообщения `[vel_control, …]`, а готовые внутренние кадры `[len, 0, group, id, данные]`, то есть ту же раскладку, что и все кадры формационного Wi-Fi (поверх неё `FA` и CRC добавляет приложение). Наш аварийный кадр `ALL_AUTOLAND` совпадает с командой «посадка» этого класса.

| Команда | Кадр (без `FA` и CRC) |
|---|---|
| калибровка | `[2,0,2,2,0,0]` |
| взлёт | `[9,0,2,3,3,0×8]` |
| зависание | `[9,0,2,3,2,0×8]` |
| посадка | `[9,0,2,3,4,0×8]` |
| скорость (`setDir`) | `[5,0,2,13,2,0,Y,X,0]`, `Y` вперёд, `X` вправо, назад и влево отрицательные, по байту со знаком |
| скорость по трём осям (`setVXYZ`) | `[5,0,2,13,6,0,Y,X,Z]` |
| поворот (`setYaw`) | `[3,0,2,14,направление,угол_lo,угол_hi]`, 0 по часовой, 1 против |
| высота (`setHigh`) | `[7,0,2,12,2,0,0,0,0,z_lo,z_hi]` |
| режим | `[10,0,2,11,6,режим,0×8]`, режимы 1 линия, 2 метки, 4 ИИ |

**Не проверено на дронах FM.** Приложение шлёт эти кадры дронам Wing через USB-пульт, а не дронам формации по Wi-Fi. Построители в `litebee/live.py` только собирают байты, нигде не вызываются и сокетов не открывают; скорость ограничена 30 см/с, поворот 0–180°, высота 20–200 см. Тесты (`tests/test_live.py`) сверяют байты с массивами из кода LiteBee Go.

Единицы скорости (см/с или иное) по подписям блоков «cm/s», но по полёту не проверены.

## Другие адреса, найденные в `main.js` (для справки)

Это одиночный режим с точкой доступа `192.168.5.1` (другое семейство роботов): WebSocket `:8266` (MicroPython REPL), TCP `:17788` (команды), TCP `:17880` (загрузка прошивки или файла), UDP `:17789`. Кадр там тот же стиль: `0xFA` + данные + CRC-16. К LiteBee Wing, который мы используем, это относится не обязательно.

## USB-пульт: обмен на COM3 (проверено на живом пульте, 2026-10-28)

Пульт со стиками определяется как «Silicon Labs CP210x USB to UART Bridge», `VID_10C4 & PID_EA60`, 115200 бод. Дрон двигали не пытались: отправлялись только запросы чтения.

Кадр от пульта: `FC FC` + длина `N` + `N` байт данных, первый байт данных это тип. Кадр к пульту: `FD FD` + длина + данные. Разбор подтверждён кодом LiteBee Go и записью.

| К пульту | От пульта | Смысл |
|---|---|---|
| `FD FD 01 E9` | `FC FC 02 E9 03` | приветствие и подтверждение связи (проверено) |
| `FD FD 01 0D` | `FC FC 04 0D FV RV ?` | версии: у нас `0D 00 6F 00`; приложение считает версию известной, только если `FV` не 0 |
| `FD FD 01 0E` | `FC FC 1F 0E` + 30 байт | пакет данных (телеметрия), идёт примерно 20 раз в секунду (проверено) |
| байт `00` раз в 500 мс | | пульс; приложение разрывает связь, если пульт молчит три такта |

Сам по себе пульт ничего не присылает: без приветствия 40 секунд тишины, стики по USB не передаются (проверено).

Первая запись (дрон FM с формационным блоком): все 295 пакетов данных нулевые, `FV` = 0. Пульт с компьютером связан, а дрона не видит.

Вторая запись (позже в тот же день, с дроном Wing, который с пультом уже летал): версия дрона `FV` = 123 (1.2.3), пульт `RV` = 111 (1.1.1), 79 пакетов за 4 секунды (около 20 в секунду), пакет не нулевой.

### Пакет данных (30 байт после маркера `0E`)

Раскладка взята из `remoteDataHandle` в `main.js` LiteBee Go и сверена с реальным пакетом:

| Байты | Поле |
|---|---|
| 0–5 | три int16: положение `x`, `y`, `z` (см); `x` и `y` это строка и столбец коврика (в LiteBee Go `pos.x`, `pos.y`) |
| 6–11 | три int16 в десятых долях градуса: крен, тангаж, рыскание |
| 12 | напряжение батареи в десятых долях вольта |
| 15 | режим (в записи 10, смысл неизвестен) |
| 16–18 | три int8: скорость по x, y, z |
| 19–28 | модули расширения (линия, метки, цвет, ИИ, датчики расстояния), не расшифровано |
| 29 | миссия |

Реальный пакет: `49 00 06 01 00 00 41 03 2e 00 4a 00 4d 00 00 0a 12 ff fa 00…00 05`. Расшифровка: положение (73, 262, 0), крен 83,3°, тангаж 4,6°, рыскание 7,4°, батарея 7,7 В, режим 10, скорость (18, −1, −6), миссия 5.

**Пульт должен быть в режиме программирования** (индикатор L4 горит зелёным, переключает кнопка K-0). В обычном режиме два замера с разницей в минуты дали байт в байт одинаковый пакет (крен 83,3° у дрона на столе: застывшее значение). После перевода в режим программирования пакет стал другим (крен 0,9°) и поток ожил.

**Живая проверка (2026-10-28, режим программирования, дрон в руках, пропеллеры сняты, 10 секунд, 97 замеров):**

| Поле | Диапазон |
|---|---|
| крен | −147,3° … 41,9° |
| тангаж | −55,7° … 58,9° |
| рыскание | −55,1° … 163,1° |
| положение x | −109 … −75 |
| положение y | −66 … 19 |
| положение z | 0 (не менялось) |
| скорость по осям | примерно от −59 до 54 |
| батарея | 7,7 В (не менялась) |

Углы следуют за наклонами рукой, положение x, y меняется при переносе дрона, то есть оценка смещения есть и без коврика. Единицы и точность положения не проверены: возможно, это накопленный сдвиг по оптическому потоку, который уходит со временем. `z` при переносе рукой остался 0.

Команда проверки: `python -m litebee wing-status` (читает только пульт, дрону ничего не отправляет). Код: `litebee/remote.py`; запись команд пульту заблокирована, пока не передан `allow_commands=True`.

## Как подключить USB-пульт к LiteBee Go и к нашей программе (разбор 2026-11-07)

**Как LiteBee Go находит пульт (прочитано в `main.js`):** функция `checkPortPath` перебирает последовательные порты и берёт те, у которых `VID:PID` равен `10C4:EA60` (CP210x) или `1A86:7523` (CH340). Порт открывается на 115200 бод. Подключение бывает двух видов: `serial` (пульт по USB) и `net` (Wi-Fi). Приём ведёт автомат `remoteDataHandle`: два байта `0xFC`, длина, данные.

**Пошагово для обычного Wing с пультом:**
1. Драйвер CP210x. В пакете `驱动包.zip` лежит `CP210x_Universal_Windows_Driver.zip`; Windows у нас уже показывает пульт как `Silicon Labs CP210x USB to UART Bridge (COM3)`, значит драйвер стоит.
2. Включите пульт, **переведите его в режим программирования** (кнопка K-0, индикатор L4 горит зелёным), пульт и дрон должны быть связаны (L2 погас, L3 погас; привязка описана в `WING_MANUAL_NOTES.md`).
3. Подключите пульт к компьютеру кабелем Micro USB.
4. В LiteBee Go выберите расширение **«LiteBee Wing»** (одиночный режим, не «Formation») и подключитесь (кнопка подключения самолёта). Приложение само найдёт порт; если порта нет, покажет «Сначала подключите самолёт».
5. Команды движения идут на пульт кадрами `FD FD len + сообщение`, а пульт передаёт их дрону по радио.

**Режим формации по Wi-Fi (дроны FM) этим путём не управляется:** там приложение работает как TCP-сервер на порту 18001 (расширение `litebeeWingFormation`).

**Живая проверка 2026-11-07 (`python -m litebee wing-status`, только чтение, дрон не двигался):** пульт ответил на приветствие; версии: пульт 1.1.1, дрон 1.2.3; 99 пакетов данных за 5 секунд; «пульт видит дрон»; батарея 8,2 В; положение (0, 0, 0) см; крен 0,6°, тангаж −0,7°, рыскание 0°; режим 10; скорость (0, 0, 0). Версия дрона 1.2.3 совпадает с версией дрона, который с пультом уже летал, то есть это обычный Wing, а не дрон формации (у FM в нашей первой записи пакеты были нулевые).
Полёт командой `wing-fly` в этот раз не запускался.

## Что остаётся неизвестным

- Принимает ли LiteBee Wing такие кадры по Wi-Fi (TCP 18001), если сформировать их самим. Приложение так не делает, значит, прошивка, скорее всего, не рассчитана на это; проверять можно только осторожно, на одном дроне.
- Что именно USB-адаптер превращает в радиокадры.
- Единицы скорости (см/с или 0,1 м/с) проверены только по подписям, не по полёту.
