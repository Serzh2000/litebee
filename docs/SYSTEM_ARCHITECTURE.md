# Архитектура системы LiteBee Wing: железо, система, службы, сеть

Сводка на 2026-11-08 (первая версия 2026-11-07). Основана на файлах образа дрона, на файлах и памяти, снятых с **живого дрона** и **живого модуля** по USB (ADB, только чтение), на побитовых образах флеша дрона и модуля. Пометки: **ПРОЧТЕНО** (в файле, в ответе устройства или в коде), **ВЫВОД**, **НЕИЗВЕСТНО**.
Подробности по частям: [FIRMWARE_ARCHITECTURE.md](FIRMWARE_ARCHITECTURE.md) (автопилот), [firmware/POSITION_MODULE_V831.md](firmware/POSITION_MODULE_V831.md) (модуль), [firmware/WING_DRONE_USB.md](firmware/WING_DRONE_USB.md) (дрон по USB), [firmware/AWLINK_TABLE.md](firmware/AWLINK_TABLE.md) (протокол приложения).

## 1. Общая схема

Система состоит из **трёх компьютеров** и пульта:

| Узел | Чип, система | Роль |
|---|---|---|
| Дрон Wing | Allwinner sun8i (A33), Linux 3.4.39-rt143 | Автопилот, Wi-Fi, видео, оптический поток |
| Модуль позиционирования | Allwinner V831 (sun8iw19), Linux 4.9.118 (MaixPy3) | Камера вниз, поиск меток, ToF, подсветка |
| Приложения | Windows (LiteBee Go), Android | Миссии, телеметрия, обновление |
| Пульт | GD32E103 (Cortex-M4) | Стики по радио 2,4 ГГц |

Связи: приложение ⇄ дрон по Wi-Fi (UDP/TCP), дрон ⇄ модуль по UART (`/dev/ttyS0`, 115200), пульт → дрон по радио. У модуля **нет сети** (раздел 5.4): с миром он связан только UART-кабелем и USB.

## 3. Дрон Wing: система и службы

**Загрузка (ПРОЧТЕНО):** загрузчик → ядро → `init` (BusyBox, `/etc/inittab`) → `/etc/init.d/rcS` → `/etc/autorun.sh`. `rcS` включает `mdev`, задаёт имя узла `sun8i`, настраивает TCP (`tcp_thin_dupack`, `tcp_retries2` = 10) и запускает `autorun.sh`. Консоль: `getty` на последовательном порту, 115200.

**`/etc/autorun.sh` по порядку (ПРОЧТЕНО):**
1. `/etc/wifi_switch.sh`: выбирает режим Wi-Fi и автопилот (раздел 4).
2. `pmonitor &` (служебный наблюдатель), `/etc/init.d/adbd.init &` (ADB по USB: `18D1:0002`).
3. Пауза 3 секунды, чтение `/netPrivate/wifiActor`.
4. Если режим `SERVER`: `cd /img_app && nice --19 ./run.sh` (запускает `VideoTransmission`).
5. `sync`, сброс буферов раздела `/netPrivate`.

**Процессы на живом дроне:**

| Режим `wifiActor` | Процессы |
|---|---|
| `CLIENT` | `init`, `flow`, `sunxi_poweroff_detection`, `wpa_supplicant`, `udhcpc`, **`pilot_f`**, `pmonitor`, `adbd`, `getty` |
| `SERVER` | `init`, `flow`, `sunxi_poweroff_detection`, `hostapd`, `udhcpd`, `ftpd`, **`pilot`**, `pmonitor`, `VideoTransmission`, `adbd`, `getty` |

`flow` запускается в обоих режимах и вычисляет оптический поток по нижней камере (OpenCV 3.4.1, закрытый алгоритм). Автопилоты `pilot` и `pilot_f` отличаются размером и содержимым (разные сборки одной базы кода).

**Образ и обновление (ПРОЧТЕНО в `/etc/ota.sh`):** скрипт обновления хранит пары разделов (основной и запасной) для ядра и корня, читает `env`, переключает раздел загрузки и записывает новый образ. Его запускает `VideoTransmission` по команде `firmware_update` (`nice --19 /etc/ota.sh …`). Проверку подписи образа мы не нашли (НЕИЗВЕСТНО).

**Файлы пользователя (`/netPrivate`, vfat):** `wifiActor` (режим Wi-Fi), `param` и `param_calib` (параметры автопилота), `config.ini` (язык, дата, часовой пояс), `record_use`, при необходимости `hostapd.conf` и `wpa_supplicant.conf` (личные копии настроек Wi-Fi).

## 4. Режимы Wi-Fi дрона

Режим задаёт одна строка в `/netPrivate/wifiActor` (ПРОЧТЕНО). Если файла нет, `wifi_switch.sh` создаёт его со значением **`CLIENT`**.

| | `CLIENT` | `SERVER` |
|---|---|---|
| Wi-Fi | Дрон подключается к сети, `wpa_supplicant` (`-Dnl80211`), адрес по DHCP (`udhcpc`) | Дрон раздаёт сеть, `hostapd` |
| Сеть | Берётся из `/netPrivate/wpa_supplicant.conf`, иначе из `/etc/wpa_supplicant.conf` (в образе указана одна сеть по умолчанию) | SSID `MR100_123456` по умолчанию; после запуска имя заменяется на `LiteBee Wing_<код>`; WPA2-PSK (CCMP), канал выбирается автоматически из 1--11, 802.11n HT20, **не более одного клиента** |
| Адрес | по DHCP | `192.168.100.1/24`, маршрут по умолчанию через себя |
| DHCP | нет | `udhcpd`: выдаёт `192.168.100.20`--`.254` (не более 4 аренд) |
| Файлы | нет | `ftpd` на порту 21 |
| Автопилот | `pilot_f` | `pilot` |
| Видео и обновление | **нет** (`VideoTransmission` не запускается) | `VideoTransmission` |

Какая система пишет в `wifiActor` и по какому событию режим меняется, мы не нашли (НЕИЗВЕСТНО). В наших наблюдениях режим сменился с `CLIENT` на `SERVER`, когда дрон унесли из помещения с нужной сетью (со слов владельца); вывод: при отсутствии сети дрон работает как точка доступа. ВЫВОД

## 5. Модуль позиционирования

### 5.1. Железо (ПРОЧТЕНО на живом модуле)

| Узел | Данные |
|---|---|
| Процессор | Allwinner **V831** (`sun8iw19`), один Cortex-A7 (ARMv7, NEON, VFPv4) |
| Память | 60 МБ ОЗУ (`MemTotal` 60 152 КБ), раздел подкачки 75 МБ |
| Хранилище | SD/eMMC `mmcblk0`, 482 МБ (раздел 5.2) |
| Камера | сенсор **OV2685** (2 Мп, MIPI) на шине I²C, адрес `0x3c` (`1-003c`); в системе загружены ещё драйверы `ov7251`, `ov9732`, `sp2305`, не используемые |
| Датчик расстояния | ToF **VI5300** на `i2c-2` |
| Светодиоды | WS2812 через `spidev1.0`; подсветка камеры: 4 канала ШИМ (`sunxi_pwm0`) |
| Линии | UART0 и UART1 (`ttyS0`, `ttyS1`), `i2c-1`, `i2c-2`, `spi1`, USB-устройство, `sdmmc0` (хранилище), `sdmmc1` (слот Wi-Fi, не используется) |
| Прочее | ISP камеры, видеовход `vinc0/vinc1`, декодер видео `cedar`, графика `g2d`, сторожевой таймер |

### 5.2. Система и разделы

Linux 4.9.118 (OpenWrt, ядро собрано Sipeed, 32-бит ARM, musl, BusyBox), стандартный образ **Sipeed MaixPy3 0.5.4** (Python 3.8, `numpy`, `pyserial`, `Pillow`, модуль `maix`, OpenCV 4.1 для C++).

| Раздел | Размер | Назначение |
|---|---|---|
| `env`, `boot` | 256 КБ, 4 МБ | Переменные загрузчика, ядро |
| `cfg` (`/mnt/cfg`) | 75 МБ | Программа производителя `firmware/maix_dist` |
| `rootfs` (`/`) | 256 МБ | Корневая система (ext4, чтение и запись) |
| `swap` | 75 МБ | Подкачка |
| `UDISK` (`/mnt/UDISK`, `/root`) | 48 МБ | USB-диск (FAT), он же рабочий каталог пользователя |

Побитовый образ: `LiteBee_firmware_original/08_position_module_flash_raw/mmcblk0_full.img`.

### 5.3. Службы и запуск (ПРОЧТЕНО)

Скрипты в `/etc/init.d`: `S00mpp` (медиаплатформа), `S01audio`, `S01logging`, `S02app` (запуск программы), `S10udev`, `S11dev`, `S12usb` (USB-устройство).
* **USB-устройство** настраивает `S12usb` через configfs: VID/PID `18D1:0002`, серийный номер `20080411`, производитель «MaixPy3», функции: диск (`UDISK`) и ADB.
* **`S02app`** выбирает, что запускать (по порядку): обновление из `maix_dist` на USB-диске, затем `/root/main.py`, затем `/root/dist/start_app.sh`, затем программа из `cfg` (`/home/firmware/keep_app.sh`).
* **Живые процессы:** `init`, `keep_app.sh`, **`app_ckh831`**, `adbd` и потоки ядра. Нет ни `sshd`, ни `telnetd`, ни сетевых служб.
* **Сторожевой таймер:** `keep_app.sh` каждые 0,2 с пишет в `/dev/watchdog` и перезапускает программу, если она упала. Если остановить сам `keep_app.sh`, модуль перезагрузится (мы это наблюдали). После четырёх падений подряд запускается сброс `factory.sh`.
* **Режим `S02app` по умолчанию на этом модуле:** запуск из `cfg` (`maix_dist`).

### 5.4. Сеть модуля (ПРОЧТЕНО на живом модуле)

* В системе **один сетевой интерфейс: `lo`** (петля). Нет `wlan0`, нет Ethernet, хотя в ядре есть `cfg80211` и слот для Wi-Fi (`sdmmc1`).
* **Единственный открытый порт: TCP 5037** (ADB). UDP-портов нет.
* Связь с внешним миром: **UART** (`ttyS1` модуля идёт к дрону; `ttyS0` модуля это разъём U0TX/U0RX наружу, к внешним устройствам вроде зуммера) и **USB** (ADB и диск).
* Следствие: до модуля нельзя добраться по Wi-Fi, только через USB или через кабель к дрону.

## 6. Сеть дрона: порты и протоколы

**Интерфейс:** `wlan0`. В режиме `SERVER` адрес `192.168.100.1`, сеть `192.168.100.0/24`.

| Порт | Протокол | Кто слушает | Что это | Уверенность |
|---|---|---|---|---|
| **9696** | UDP | `pilot` / `pilot_f` (`bind`, `select`) | Команды и телеметрия awlink (мобильное приложение Wing) | ПРОЧТЕНО (код, приложение) |
| 9697 | TCP | `pilot` (`bind`, `listen`) | Второй канал awlink, назначение не выяснено | ПРОЧТЕНО (код), назначение НЕИЗВЕСТНО |
| 13146 | UDP | `pilot` (`bind`) | Порт «объявлений» дронов формации: наш `litebee` использует UDP 13146 для связи с дронами (`proto.UDP_REMOTE`) | ПРОЧТЕНО (код), назначение ВЫВОД |
| **18001** | TCP | `pilot` / `pilot_f` (клиент: `connect`) | Подключение дрона к TCP-серверу программы на ПК (LiteBee Go или наш `litebee`): протокол формации, `proto.TCP_PORT` = 18001 (число `0x4651` в коде) | ПРОЧТЕНО (код), назначение ВЫВОД |
| 21 | TCP | `ftpd` | FTP, корень `/` файловой системы, не более 2 пользователей | ПРОЧТЕНО (`ftpd.conf`) |
| 7070 | RTSP | `VideoTransmission` | Видео с камеры (по приложению LiteBee Go) | ВЫВОД (по приложению), в бинарнике порт не найден |
| 5037 | TCP | `adbd` (на модуле) | ADB | ПРОЧТЕНО |

**`VideoTransmission`** (только режим `SERVER`; ПРОЧТЕНО по строкам): принимает **JSON-команды** (разбор `json_tokener`), ограничено числом клиентов («only suport %d client»), умеет работать с файлами на карте (список видеофайлов, миниатюры, `totalSpace`, карты до 32 ГБ), менять имя сети (`hostapd_cli -i wlan0 set ssid …`, правка `/netPrivate/hostapd.conf`) и запускать **обновление** прошивки (`firmware_update` → `nice --19 /etc/ota.sh`). Формат JSON-команд не разобран. НЕИЗВЕСТНО

**Безопасность (ПРОЧТЕНО):**
* ADB по USB даёт оболочку **root без пароля** (и на дроне, и на модуле).
* FTP на дроне открыт с **корнем файловой системы** и фиксированным логином/паролем, записанными в `/etc/ftpd.conf` (значения не копируем в документы).
* Пароль точки доступа по умолчанию простой и общий для всех дронов (лежит в `/etc/hostapd.conf`). Сеть клиента по умолчанию в образе тоже указана открыто (`/etc/wpa_supplicant.conf`).
* На модуле нет сетевых служб, что снижает риск.

## 7. Сквозной путь данных (ПРОЧТЕНО)

1. Камера модуля (OV2685) → ISP → кадр 160×120.
2. `app_ckh831` (imlib, tag36h11) → метка: номер, смещение, расстояние, угол.
3. Кадр из 22 байт по UART (`ttyS1` модуля → `ttyS0` дрона).
4. `pilot_f` / `pilot`: конечный автомат приёма, разбор, формула → положение (строка, столбец, высота).
5. Регуляторы → драйвер моторов `/dev/STM8s`.
6. Телеметрия awlink по UDP 9696 → приложение.

## 8. Живые опыты, не только чтение (2026-11-07)

* **USB-пульт Wing** (CP210x, COM3): чтение состояния и два чистых полёта через `python -m litebee wing-fly`; скорость в см/с, выбег после стопа 10-13 см. Подробно: [PROTOCOL_SINGLE.md](PROTOCOL_SINGLE.md). ПРОЧТЕНО (проверено вживую).
* **Зуммер на разъёме U0TX/U0RX модуля:** кадр `AD FA 01 нота длительность сумма`; мелодия с компьютера по Wi-Fi через UDP-ретранслятор на дроне (порт 5555, живёт в памяти, запуск по ADB). Подробно: [firmware/BUZZER_EXTENSION.md](firmware/BUZZER_EXTENSION.md). ПРОЧТЕНО (проверено на слух).
* Во флеш дрона и модуля ничего не записывалось. В оперативную память (`/tmp`) копировались только наши небольшие программы.
