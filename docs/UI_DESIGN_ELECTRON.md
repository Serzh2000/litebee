# Litebee IDE — дизайн интерфейса (Electron, текущее приложение)

Заменяет `docs/UI_DESIGN.md` (версия на PySide6, устарела). Описывает `desktop/` — то, что собирается `npm run dist` и выходит релизами `v*` (portable `.exe`, `electron-builder.yml`).

## Архитектура экрана

Точка входа `App.tsx`: `Sidebar` (слева, узкая, режим код/карта и ссылка на проект) + `TopBar` (сверху, порядок подготовки и аварийная посадка) + основная сцена (`<main className="sheet">`), в которой `.stage` делит место между картой (`well`, слева) и правой панелью (`RightPanel`).

- **Карта (`well`)** — либо 2D (`MatChart.tsx`, SVG, коврик сверху) либо 3D (`Mat3D.tsx`, Three.js, модель дрона `litebee_fm10.glb`); переключатель хранится в `localStorage` (`litebee.view`). Над картой `AreaBar` (выбор четверти/всего коврика, лимит высоты, переключатель вида, метки QR, пути шоу).
- **Правая панель (`RightPanel`)**, вкладки: **Партитура** (`Timetable.tsx` — светодиод и, с 2026-11-16, ноты зуммера на той же дорожке), **Код** (`Inspector.tsx` + `DroneEditor.tsx` для выбранного дрона), **Проверки** (`SidePanel.tsx`), **Справочник** (`Reference.tsx`, из `litebee/reference.py`), **Дроны на связи** (`LivePanel.tsx`).
- Панель можно свернуть целиком (кнопка в `TopBar`, состояние `inspectorOpen`), карта тогда растёт на всю ширину.
- **Старт и мастер:** `StartScreen.tsx` (три способа начать + недавние) и `NewProjectWizard.tsx` (чистый проект или встроенный пример) — модальные экраны над рабочим пространством (`inert` на фоне).

## Палитра и токены

Один файл: `desktop/src/renderer/src/styles/tokens.css`. Светлая и тёмная тема — два набора значений одних и тех же имён под `:root` и `:root[data-theme='dark']`; переключатель — `ThemeSwitch.tsx` / `useTheme.ts`.

| Назначение | Токен | Светлая | Тёмная |
|---|---|---|---|
| Фон окна | `--ground` | `#f0f0ed` | `#111113` |
| Лист/панель | `--surface` | `#ffffff` | `#1b1b1e` |
| Поднятая поверхность, сцена | `--raised` | `#f6f6f3` | `#202023` |
| Текст | `--text` | `#131416` | `#f1f1ef` |
| Вторичный текст | `--muted` | `#5d5f60` | `#b4b4bb` |
| Акцент (единственный) | `--accent` | `#1b6c80` | `#8ecbd2` |
| Авария | `--negative` / `--emergency` | `#c4242a` | `#f07a7e` / `#c4242a` |
| Шрифт интерфейса | `--font-ui` | IBM Plex Sans | — |
| Шрифт чисел/кода | `--font-num` | IBM Plex Mono | — |

Старые имена компонентов (`--ink`, `--ink-2`, `--sheet`, `--paper`, `--danger` и т. п.) — алиасы этих же токенов, не вторая палитра (см. комментарий в начале `tokens.css`). Цвет один акцентный (`--accent`), цвета светодиодов дронов берутся из данных шоу, не из темы.

Единственное осознанное исключение из токенов: `Emergency.css` — три хардкодных оттенка красного для кнопки аварийной посадки (комментарий в файле: «единственный залитый красный экрана»).

## Партитура (`Timetable.tsx`)

Дорожка на дрона: полоса цвета светодиода во времени плюс (с 2026-11-16) нотки зуммера — маленькие метки, поднятые по высоте тона, с именем ноты для выбранного дрона. Вторая часть не занимает отдельного места в раскладке: если у дрона нет шагов `buzz`, на дорожке просто ничего дополнительно не рисуется.

## 3D-вид (`Mat3D.tsx`)

Модель дрона из `assets`, пропеллеры крутятся в воздухе, светодиод светится в цвете шоу, реальные дроны на связи — кольцо и подпись IP. Управление мышью: тянуть — поворот камеры, колесо — масштаб, правая кнопка — сдвиг; перетаскивание дрона переставляет его стартовую клетку.

**Известный пробел в доступности (2026-11-21):** холст WebGL ничего не даёт скринридеру сам по себе. Контейнер подписан (`role="img"`, `aria-label`, называет выбранного дрона), но **перетаскивание дрона в 3D не имеет клавиатурной замены** — тот же результат (поставить дрона на клетку) сейчас доступен только через 2D-вид (`MatChart.tsx`), который разбирает клавиатуру и имеет собственную подпись.

## Доступность: что сделано, что нет

- Горячие клавиши: Esc (авария), Ctrl+O/Ctrl+S, стрелки в партитуре (время и выбор дрона), +/−/0 на карте.
- `aria-label`/`role` расставлены по контейнерам экранов (`DroneEditor`, `MatChart`, `StartScreen`, `Mat3D` и др.), а не по каждому элементу внутри — по тому же принципу, что и в остальном коде: один описывающий контейнер лучше, чем шум из одинаковых подписей.
- Не сделано: полная клавиатурная замена перетаскивания в 3D-виде (см. выше); живое объявление смены выбранного дрона в 3D для скринридера (сейчас только статичная подпись контейнера, без `aria-live`).

## Чего не делаем

Декоративная анимация, видео с дрона, ручное управление скоростью без карты — как и в старом дизайне (`UI_DESIGN.md`), эти решения не изменились.
