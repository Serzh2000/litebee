# Litebee IDE — проект

Десктопное приложение (Windows) для программирования дронов LiteBee Wing из набора FM-10 на Python.
Заменяет Scratch-часть LiteBee Go, остаётся совместимым с его проектами `.lbg`.

## Что уже доказано на живых дронах

- Дрон подключается к ПК по TCP (порт 18001) после UDP-объявления адреса ПК (порт 13146, широковещательно).
- Кадр: `0xFA` + `[len, 0, group, id, данные]` + CRC-16 (init 0xFFFF, отражённый 0x8408, без финального XOR, младший байт первым).
- Телеметрия (21 байт): x, y, z, батарея, флаг, контрольная сумма миссии, номер, часы.
- Миссия: очистка, шаги, старт. Цвет (RGB-шаг) работает без взлёта.
- Взлёт, зависание и посадка работают (calibrate / takeOff / moveZ / autoLand), время в 0,1 с, высота в см.
- Движение по клеткам коврика, шаг moveXY (формация cmd 3): 4 полёта на двух дронах, обе оси, любой курс носа. Данные шага: `struct.pack("<HH", 40*строка, 40*столбец)` и 8 нулевых байт, клетка = столбец + 12 * строка (0..143), первое число — ось строк (y), второе — ось столбцов (x), абсолютные координаты коврика в см. Время шага — накопленное время конца (0,1 с), как у остальных шагов.

## Что не доказано (ограничения)

- Дрон выполняет миссию с moveXY, только если у него есть позиция по коврику на старте. Только что включённый дрон сообщает x = y = 0 на земле (это НЕТ позиции, а не клетка 0). Позиция появляется в полёте примерно на 30 см и остаётся после посадки. Миссия из одной калибровки позицию не даёт. Без позиции дрон прерывает миссию через ~3 с без взлёта.
- Точность по коврику: около ±10-15 см, перелёт до ~20 см. Это не проверялось на нескольких дронах рядом.
- Шаги moveXYZ (`code_z`), `circle`, `circle_z` и всё остальное: формат на проводе не проверен, загрузка отказывает.
- Относительные команды (`setDir`, `setYaw`, `setHigh`) LiteBee Go отправляет только по USB-serial, формационный Wi-Fi-обработчик их не знает (`docs/PROTOCOL_SINGLE.md`). Принимает ли дрон такие кадры по Wi-Fi, не проверено.
- Несколько дронов и синхронный старт не проверялись. Часы дронов в телеметрии показывают 0.
- Видео с дрона недоступно (камерные модули C06/C10 имеют собственные точки доступа).
- Lua на дроне невозможен. Язык шоу: Python.

```

  mission.py            шаги миссии, упаковка, проверка контрольной суммы
  show.py               описание шоу (Drone/Show), симулятор, проверки сближения
  reference.py          справочник функций шоу: данные (имя, сигнатура, параметры, пример, статус), одна правда для панели и подсказок
  lbg.py                импорт проектов LiteBee Go (.lbg)
  safety.py             лимиты (в том числе настраиваемый лимит высоты) и проверки перед стартом
  flight.py             загрузка, сверка контрольной суммы, старт, наблюдение, аварийная посадка
  loader.py             загрузка шоу из .py (совместимо с `from litebee_show import Show`) и .lbg; код .py идёт в отдельном процессе с лимитом времени
  show_worker.py        процесс-исполнитель кода шоу (`python -m litebee.show_worker`), отдаёт шаги обычным JSON
  cli.py                python -m litebee: listen, color, hop, simulate, import-lbg
app/                    PySide6
  main_window.py        окно: порядок подготовки, карта, колонка кода, партитура, нижняя полоса
  editor.py             редактор кода с подсказками для litebee API (читает litebee/reference.py)
  reference_panel.py    панель «Справочник» (F1): поиск, темы, примеры, вставка в редактор
  preview.py            вид сбоку, обёртка над картой коврика
  cue_sheet.py          партитура света: дорожка на дрона, полоса цвета светодиода, штрихи шагов
  preflight.py          порядок подготовки к полёту (четыре шага, состояние значком и словом)
  mat_map.py            карта коврика: клетки, масштаб и сдвиг, план шоу, живые позиции дронов
  drone_art.py          нарисованная модель дрона (QPainter), значок и картинка
  drones_panel.py       нижняя полоса: фишки дронов, батарея, клетка, состояние, выбор «кто летит»
  session.py            связь окна с ядром: состояния дронов, загрузка и старт в потоках
  theme.qss, theme.py   единственное место цветов и шрифтов (токены из docs/UI_DESIGN.md)
tests/                  тесты и FakeDrone (только 127.0.0.1, порт выбирается системой)
docs/DESIGN.md          этот файл
```

Ядро (`litebee/`) не зависит от интерфейса и работает из командной строки.

## Окно приложения

Подробно: `docs/UI_DESIGN.md` (версия 2).

- Вверху порядок подготовки: «Проверить», «Загрузить», «Взвести», «Старт».
- Слева главное: карта коврика (вид сверху, вид сбоку), справа колонка «Код | Проверки | Журнал» (скрывается, Ctrl+E).
- Под картой партитура света (дорожка на дрона) с общим временем, внизу фишки дронов (IP, батарея, клетка, состояние).
- Всегда на виду: красная кнопка «Аварийная посадка».

## Безопасность

- Взлёт только после явного «взвести»; без него загрузка и проверки, но моторы не запускаются.
- Проверки перед стартом: батарея, предельная высота, минимальное расстояние между дронами из симулятора, разрешённые IP.
- Перед стартом каждая миссия сверяется с дроном по контрольной сумме.
- Аварийная посадка при любой ошибке, потере связи и по кнопке.
- Режим без дронов: всё можно писать и проверять на симуляторе.

## Этапы

1. Ядро: перенести проверенный код из скриптов (`drone_probe`, `drone_color`, `drone_hop`, `litebee_show`, `lbg_to_py`) в пакет, написать тесты.
2. Командный интерфейс: список дронов, цвет, взлёт/посадка, загрузка миссии.
3. Окно: загрузка, симуляция, старт с аварийной кнопкой.
4. Несколько дронов и синхронный старт (нужны живые дроны).
5. Редактор с превью и импортом `.lbg`.
6. Упаковка в один `.exe`.

## Открытые вопросы

- Как дрон понимает время старта, если его часы в телеметрии равны 0.
- Формат шагов moveXYZ (`code_z`) и circle на живом дроне.
- Движение по клеткам для нескольких дронов одновременно (столкновения при перелёте, общий старт).
- Относительные команды по Wi-Fi, камера, AprilTag как маркер позиции.

## Реализация этапов 1-3

- Загрузка в дрон умеет только доказанные шаги (calibrate, takeOff, moveZ, autoLand, RGB, moveXY). `code` пакуется в moveXY. `code_z`, `circle`, `circle_z` работают в симуляции, но загрузка для них отказывает до проверки формата на живом дроне.
- В окне одновременно загружается и стартует один дрон; несколько дронов откроем после проверки на живых дронах (этап 4).
- Правило времени старта перенесено из скриптов без изменений: `int(0.1 * (clock + 300))`, если дрон сообщает часы, иначе счётчик ПК + 30 (0,1 с). Живые дроны сообщают 0, поэтому проверена только вторая ветка.

## Настраиваемый лимит высоты

- `MAX_HEIGHT_CM = 150` (он же `DEFAULT_MAX_HEIGHT_CM`) остался значением по умолчанию. Рабочий лимит задаёт пользователь: поле «Лимит высоты» на панели инструментов (запоминается в `QSettings`, ключ `limits/max_height_cm`) и `--max-height` в `hop` и `simulate`.
- Границы жёсткие и не настраиваются: нижняя `MIN_TAKEOFF_CM` (20 см), верхняя `HARD_MAX_HEIGHT_CM` (200 см). Их проверяет одна функция `resolve_max_height()`: значение вне границ, не целое или не число даёт `SafetyError`. Поле в окне не пускает за границы, из настроек выше 200 или мусор не читается (остаётся 150), CLI отказывает с кодом 1.
- Лимит передаётся явным параметром `max_height_cm` (по умолчанию 150): `check_show`, `check_mission`, `preflight`, `run_mission`, `hop_mission` (проверка высоты одиночного прыжка). Окно держит его в `FlightController.max_height_cm`, он идёт в `preflight` при загрузке. Старт повторно отказывает, если миссия выше текущего лимита (лимит снизили после загрузки).
- Лимит влияет только на проверку высоты. Лимит зависания, список доказанных шагов, коврик, сближение, батарея и белый список IP проверяются как раньше. Шаги `code_z`, `circle`, `circle_z` по-прежнему не загружаются.
- В окне смена лимита делает проверку устаревшей: «Загрузить» и «Старт» ждут нового «Проверить». Пунктирная линия вида сбоку и её подпись показывают действующий лимит, диалог перед стартом пишет «Высота до N см (лимит M см)».

## Лимит времени проверки

- Код шоу — программа пользователя, он может зациклиться. `load_show_source(source, filename, timeout=SHOW_TIMEOUT_S)` запускает его в отдельном процессе (`python -m litebee.show_worker`, обычный `subprocess`, не поток: поток нельзя убить) и убивает процесс через `SHOW_TIMEOUT_S = 5` с. Ошибка `ShowTimeoutError` (наследник `ShowLoadError`): «Шоу выполняется дольше 5 с. Проверьте циклы в коде». `timeout=None` выполняет код в текущем процессе, как раньше.
- Через границу процесса идёт простой JSON: имя шоу и шаги дронов (вид, секунды, аргументы, строка). Родитель собирает `Show` заново, поэтому `Show`, `check_show`, симулятор и CLI не изменились. Ошибки кода шоу (строка, тип) приходят так же. Вывод `print` из кода шоу уходит в stderr, на результат не влияет. Сам процесс завершается и по своему сторожу (лимит + 5 с), если родитель пропал.
- Защита от разрастания: больше `MAX_SHOW_STEPS = 10000` шагов у одного дрона обрывает шоу сразу, больше 10000 шагов суммарно отклоняется после выполнения. Сообщение: «Шоу содержит больше 10000 шагов. Проверьте циклы в коде».
- В окне «Проверить» не блокирует интерфейс: процесс ждёт рабочий поток, результат возвращается сигналом в основной поток. Пока идёт проверка, кнопка неактивна и называется «Проверяю…», «Загрузить» и «Старт» ждут. Новый документ или закрытие окна убивают процесс проверки. Время настраивается атрибутом `MainWindow.show_timeout`. `MainWindow.check()` остаётся блокирующим вариантом для тестов и скриптов (цикл событий при этом работает).
- Не покрыто: потребление памяти кодом шоу не ограничено (процесс убивается только по времени), для будущей упаковки в один `.exe` запуск `python -m litebee.show_worker` придётся заменить на запуск самого exe с особым ключом.

## Движение по клеткам (moveXY)

- Упаковка: `mission.xy_data(cell)` (клетка 0..143, иначе `ValueError`), `show.drone_to_mission` превращает `code` в moveXY. Тест сравнивает кадры с эталоном с живого дрона: калибровка 5 с, взлёт 50 см 5 с, moveXY на клетку 97 за 4 с, посадка; контрольная сумма 6. В миссию помещается не больше 255 шагов (счётчик шагов в кадре один байт), больше — `UploadUnsupported`.
- Позиция дрона: `Telemetry.has_fix` (не x = y = 0) и `Telemetry.cell` = `round(x/40) + 12*round(y/40)` (None без позиции или за пределами коврика).
- Перед загрузкой и ещё раз перед стартом для миссии с moveXY (`safety.check_position`, внутри `preflight` и `start_mission`; `FlightController.start` проверяет до запуска потока): (1) у дрона должна быть позиция, иначе отказ с текстом «У дрона нет позиции по коврику. Поставьте его на коврик и сделайте короткий взлёт на 50 см, затем повторите»; (2) расстояние от дрона до первой клетки движения шоу не больше `MAX_START_DISTANCE_CM` = 200 см, иначе отказ с номером клетки, на которой стоит дрон, и клетки, которую ждёт шоу. Собственное движение дрона абсолютное, неверная стартовая клетка отправила бы его через весь коврик. Миссии без moveXY позиции не требуют.
- Окно: карточка дрона показывает «Клетка N», «Нет позиции» или «Вне коврика». «Загрузить» и «Старт» неактивны с этим же объяснением в подсказке. Диалог перед стартом пишет «Дрон на клетке N, первое движение шоу к клетке M».
- Проверка шоу: предупреждение (не ошибка), если средняя скорость перехода `code` / `code_z` выше `MAX_LEG_SPEED_CM_S` = 100 см/с, и справка про стартовую клетку. Короче точности дрона (±10-15 см) переход не считается проблемой. Проверки сближения и высоты прежние.
- Один дрон за раз остаётся: несколько дронов не проверялись. Оба настоящих шоу в `shows/` содержат `circle` или `code_z` у каждого из 10 дронов, поэтому загрузить их по-прежнему нельзя. Высоту 160 см они проходят при лимите 170 см (ошибок высоты нет), но это шоу на 10 дронов.
